# mosque.build — Pitch, Team, PWA + Expo Context

## Product thesis
mosque.build should become the shared infrastructure layer for mosque discovery, planning, design, financing, construction, operations, endowment and preservation.

## Delivery model
- Public web and SEO/AEO surface: Next.js.
- Installable PWA behavior for applicable authenticated web workflows.
- Native iOS/Android: Expo Router.
- Shared backend: Supabase/Postgres/Auth/Storage with strict RLS.
- Shared TypeScript domain packages.
- Three.js professional design editor starts web-first; mobile receives project viewing, field capture and lighter editing first.
- The public and private products use the same canonical mosque, project, source, cost, component, supplier and operations records.

## Product quality rule
Do not optimize for feature-count screenshots. Every feature must become operationally complete: permissions, data provenance, offline/failure states, tests, logging, accessibility, admin workflows and documentation.

## Team rule
The product cannot be built credibly by software engineers alone. Mosque architecture, operations, land use, cost estimation, waqf/finance, religious review, accessibility, safety and historic preservation all require named expert ownership.

## Pitch
The platform is not merely “software for mosque donations.” It is the lifecycle operating system and knowledge graph for the physical and institutional mosque.
