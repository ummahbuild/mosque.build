# mosque.build — Cost Intelligence + Scenario Context

The cost system must never behave like a single global price list.

Every price is a dated observation attached to a geography, currency, source, unit, scope, tax treatment, delivery/install scope and confidence. Estimates are immutable snapshots; users explicitly rebase copies to updated FX, indices and quotes.

## Estimating hierarchy
1. Actual executed/awarded project rates where reusable and rights permit.
2. Current supplier/contractor quotes.
3. Recent regional public tender/unit-rate evidence.
4. Indexed historical local quotes.
5. Imported-product supplier price + actual/provisional landed-cost model.
6. Global commodity/trade indicators for trend/sensitivity only.
7. Parametric placeholder assumptions only when clearly labeled and never presented as market facts.

## Local/import comparison
Compare the complete installed/landed result, not sticker price:
product + origin transport + freight + insurance + customs/tax + port + inland + storage + install + commissioning + FX risk + lead-time risk.

## Multiple mosque mockups
A project can retain many design scenarios and branches. Geometry, program, regulatory assumptions, material choices and cost snapshots are versioned independently but linked. Updating FX never silently rewrites an old board-approved budget.

## Kenya
Use CBK for official indicative KES FX, KNBS CIPI for construction-input normalization, and KRA/EAC rules for customs. Exact tariff duty requires actual HS classification/current tariff verification.
