# mosque.build — Completeness / Cross-Lifecycle Context

This module fills the gaps between planning, design, construction and operation.

## Core lifecycle
Community need -> Owner/Community Requirements -> design response -> cost/permit impact -> approved baseline ->
procurement requirement -> submittal -> installation -> inspection -> commissioning -> handover ->
asset register -> preventive maintenance -> post-occupancy feedback -> future renovation.

## Information management
Use ISO 19650 concepts as reference for versioned/organized information management. Support openBIM exchange through IFC, model-linked issues through BCF, and machine-readable information requirements through IDS where useful.

## Commissioning
Commissioning is not a final-day checkbox. Capture Owner's Project Requirements early, review design against them, verify installations, perform functional tests, train operators, close issues, and retain seasonal/deferred tests.

## Operational continuity
Every maintainable object installed during construction should inherit procurement, warranty, supplier, commissioning, manual and location information into the operating asset register.

## Governance
Mosque committees need explicit decision rights, approval thresholds, conflict disclosures, restricted-fund controls and immutable decision history.

## Safety/data
Security-sensitive information, safeguarding data, payment data and incident records use stronger access controls than public mosque-directory information.
