# mosque.build Product Context

## One-line pitch
**From an empty plot—or an existing room—to a living Muslim institution.**

mosque.build helps communities **design, permit, fund, source, build, open, operate, endow, and preserve mosques** with better coordination, transparency, and institutional memory.

## What the product is
A lifecycle coordination system connecting:
- community need and demographics,
- parcel/site/adaptive-reuse feasibility,
- qibla-aware 2D/3D planning,
- mosque-specific program and capacity,
- engineering review gates,
- jurisdiction-specific compliance navigation,
- cost scenarios and lifecycle cost,
- fundraising, donations, sponsorships, and waqf,
- products, books, local sourcing, vendors and professionals,
- RFQs, quotes, samples, submittals and procurement,
- construction schedule, evidence, RFIs, change orders and inspections,
- commissioning, occupancy readiness and handover,
- assets, maintenance, programs and post-occupancy learning.

## What it is not
- Not a replacement for architects, engineers, authorities, scholars, lawyers, accountants, contractors or other licensed/qualified professionals.
- Not a generic "AI mosque generator."
- Not a donation-only site.
- Not a 3D renderer with a mosque skin.
- Not a claim that global regulatory, price, product or scholarly data is complete.

## Core principle
> Do not merely help a community construct a building. Help it create an institution it can afford to operate, maintain, program, and preserve for generations.

## Persistent project object
**My Mosque** is the canonical project workspace.

Every modeled object should have stable IDs linking:
requirement → geometry → quantity → specification → cost → schedule → product → submittal → issue → inspection → commissioning → handover → asset → maintenance → post-occupancy lesson.
