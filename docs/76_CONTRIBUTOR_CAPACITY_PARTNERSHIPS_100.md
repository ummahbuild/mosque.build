# Contributor capacity and partnerships — next 100 features

Status: `specified`. These are proposed extensions to the current `executable`, device-local capacity planner. A numbered item is not implemented merely because it appears here.

## Product boundary

This plan turns project work into safe, bounded opportunities to contribute. It must not become a public people directory, an unsupervised recruitment system, a credential verifier, an employment platform, or a list of implied partners. Shared project/member records require authentication and RLS. Personal contacts, identity evidence, safeguarding records, contracts and payments belong in appropriately secured systems. Professional, religious, legal, employment, safeguarding and partnership decisions retain human review gates.

## Capability demand and work packaging (1–15)

1. Add outcome-based work packages that split broad needs into independently reviewable contributions.
2. Add acceptance criteria to every work package so contributors know what useful completion means.
3. Add prerequisite skills with `required`, `helpful` and `learn-on-task` distinctions.
4. Add estimated effort ranges instead of relying only on single-hour estimates.
5. Add recurrence patterns for one-off, weekly, monthly, milestone and on-call contributions.
6. Add earliest-start and needed-by windows linked to the integrated schedule.
7. Add work-location constraints for remote, site, workshop, authority-office and community-session tasks.
8. Add language needs for research, translation, engagement and community review tasks.
9. Add accessibility requirements for meetings, documents, tools and physical participation.
10. Add equipment and software prerequisites without naming preferred vendors as endorsements.
11. Add cost-bearing flags for travel, data, printing, testing, samples and protective equipment.
12. Add supervision-level requirements for independent, paired and closely supervised work.
13. Add regulated-work flags for architecture, engineering, fire, cost, legal and religious review.
14. Add reusable contribution templates for research, source review, testing, translation and documentation.
15. Add project-phase capacity baselines that preserve revisions instead of overwriting earlier assumptions.

## Contributor pathways and sustainable participation (16–30)

16. Add an anonymous self-assessment that produces a role profile without storing identity details.
17. Add contribution-intensity choices for micro-task, short sprint, recurring role and advisory review.
18. Add preferred communication-mode requirements without storing personal contact channels.
19. Add timezone overlap windows for remote collaboration planning.
20. Add availability confidence so tentative capacity is not presented as committed capacity.
21. Add maximum-concurrent-assignment limits per role profile.
22. Add planned-break and unavailable-period records to prevent volunteer overload.
23. Add a contributor pause action that safely releases future proposed allocations.
24. Add a return pathway showing changed context, open work and required re-orientation.
25. Add beginner contribution pathways with bounded tasks and named supervision roles.
26. Add experienced-practitioner pathways focused on reviews, decisions and mentorship.
27. Add student and apprentice pathways with explicit learning outcomes and qualified oversight.
28. Add local craft pathways for mockups, samples, repair knowledge and fabrication review.
29. Add lived-experience review pathways for women, disabled people, older people, youth and caregivers.
30. Add translated and plain-language opportunity briefs generated from the same canonical work package.

## Matching and allocation intelligence (31–43)

31. Rank potential alignment using transparent discipline, phase, availability and supervision inputs.
32. Explain every match factor and every mismatch without using opaque suitability scores.
33. Subtract existing allocations before displaying remaining contributor capacity.
34. Calculate need coverage from proposed and confirmed allocations separately.
35. Prevent one capacity offer from being double-counted across competing needs.
36. Add partial-coverage suggestions that combine several bounded offers for one work package.
37. Add continuity warnings when a critical task depends on one contributor role.
38. Add handover-overlap suggestions when a role is scheduled to leave before completion.
39. Add phase-transition prompts when design contributors should brief construction or operations roles.
40. Add conflict-of-interest prompts where a contributor may also bid, approve, pay or inspect.
41. Add role-separation checks for procurement preparation, evaluation, approval and payment.
42. Add local-knowledge weighting only when the project team explicitly marks it relevant.
43. Add a manual match override that requires rationale and never changes underlying capability evidence.

## Onboarding, support and recognition (44–56)

44. Add role-specific onboarding checklists linked to project context and safety boundaries.
45. Add a minimum project orientation covering purpose, governance, privacy and decision authority.
46. Add site-induction requirements for anyone entering an active construction site.
47. Add safeguarding-induction gates for work involving children or vulnerable people.
48. Add data-handling induction for community, location, financial and project-member records.
49. Add source-quality induction for permit, cost, religious and architecture research.
50. Add mentor assignment records using project roles rather than public personal profiles.
51. Add scheduled check-in prompts based on assignment risk and duration.
52. Add structured help requests for blocked contributors.
53. Add feedback loops covering clarity, support, workload, inclusion and psychological safety.
54. Add contribution acknowledgements requiring contributor consent before public attribution.
55. Add private completion records that distinguish contribution from professional approval.
56. Add portable, consented contribution summaries contributors can use without exposing project data.

## Partnership development and mutual value (57–71)

57. Add partnership archetypes for education, professional review, craft, community service, funding and operations.
58. Add a shared-outcome canvas separating community value, partner value and project value.
59. Add non-financial contribution fields for space, expertise, equipment, training, data and outreach.
60. Add project contribution fields for learning access, visibility, research feedback and community service.
61. Add partnership assumptions that must be validated before outreach.
62. Add a permission-to-contact gate without storing contact details in the exported plan.
63. Add meeting-preparation briefs with objectives, boundaries, questions and decision authority.
64. Add partnership option comparison without automatically recommending an organization.
65. Add exclusivity and dependency-risk prompts before a project relies on one partner.
66. Add reputation, governance, conflicts, safeguarding and delivery-capability due-diligence checklists.
67. Add reciprocal accountability measures instead of measuring only the partner’s obligations.
68. Add memorandum-of-understanding preparation fields with explicit legal-review status.
69. Add pilot partnership scopes with exit criteria before long-term commitment.
70. Add partnership health reviews for outcomes, burdens, unresolved issues and renewal decisions.
71. Add responsible exit and handover plans that protect community services and project records.

## Governance, safety and accountability (72–84)

72. Add decision-right matrices for sponsor, project team, professional, authority and community review.
73. Add consent-state history for allocations, attribution and partnership participation.
74. Add credential-review records that store verification references rather than sensitive credential files.
75. Add credential-expiry prompts for regulated work.
76. Add professional-scope boundaries stating what each reviewer is and is not accepting responsibility for.
77. Add safeguarding review gates with restricted references and no sensitive case content.
78. Add grievance and concern-routing guidance outside the public planning export.
79. Add code-of-conduct acknowledgement status per role allocation.
80. Add conflict declarations with restricted detail and visible resolution status.
81. Add approval separation so a contributor cannot confirm their own allocation or deliverable acceptance.
82. Add immutable review events for proposed, confirmed, paused, declined and ended allocations.
83. Add retention and deletion schedules for capacity and partnership planning records.
84. Add share-safe export redaction tests for any future fields that could become identifying.

## Integration, reporting and delivery (85–100)

85. Link capability needs to schedule activities and milestones by stable identifiers.
86. Link work packages to design, permit, funding, procurement, construction and operations records.
87. Show capacity gaps beside affected tasks in My Project rather than only on the contribute page.
88. Add phase-level capacity heatmaps with accessible text equivalents.
89. Add a responsibility-and-capacity view that distinguishes ownership from available labor.
90. Add forecast scenarios for reduced, working and expanded contributor capacity.
91. Add a critical-capability register for safety, approvals, procurement and commissioning.
92. Add capacity-gap actions to recruit, train, partner, procure professional services, defer or reduce scope.
93. Add partnership dependencies to the risk register and integrated schedule.
94. Add contribution costs to cost planning without assigning invented rates or currencies.
95. Add onboarding and supervision effort to capacity calculations so support is not treated as free.
96. Add project-package migration support for future schema versions.
97. Add import previews that surface collisions without overwriting allocations or partnership records.
98. Add authenticated collaboration only after project/member RLS, authorization and security tests exist.
99. Add accessibility, keyboard, mobile, offline, sync-conflict and share-safe export integration tests.
100. Add a production-readiness review requiring privacy, security, safeguarding, professional and community sign-off.

## Recommended delivery sequence

- **Release A — stronger local planning:** 1–15, 31–43, 85–97.
- **Release B — contributor experience:** 16–30 and 44–56.
- **Release C — partnership governance:** 57–84.
- **Release D — shared production use:** 98–100 only after authenticated storage, RLS and review infrastructure are verified.

## Required test plan

- Unit tests for matching, remaining capacity, coverage, recurrence, conflicts and schema migrations.
- Integration tests for schedule, project package, risk, cost and My Project handoffs.
- RLS and authorization tests before any shared project or member data is introduced.
- Accessibility tests for keyboard flow, focus, announcements, charts and narrow-screen layouts.
- Mobile/web parity and offline/conflict tests if the planner becomes cross-platform.
- Share-safe provenance and redaction tests for exports and imports.
- Human review gates for employment, safeguarding, professional, religious, partnership and community decisions.
